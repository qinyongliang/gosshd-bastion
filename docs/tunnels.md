# 持久端口转发（TCP / UDP）

控制台的「隧道管理」分为「端口转发」和「HTTP 转发」。端口转发用于配置入口机器、监听地址/端口、出口机器、目标地址/端口，以及永久或定时启用。

监听端口下方可勾选 **TCP**、**UDP**，支持同时勾选，默认仅勾选 TCP，至少选择一项。两者共用配置的端口号，但分别监听 TCP/UDP；每个报文只转发到目标的相同协议端口，不进行 TCP/UDP 协议转换。任一监听失败时会撤销另一项监听，避免部分启用。

UDP 支持堡垒机和 Agent 作为入口、出口，沿用现有直连/中转通道。普通 SSH 机器（含位于 Agent 后的 SSH 机器）仅支持 TCP；选择 UDP 时不可将其作为端点。UDP 按来源 IP 和端口维护独立会话，保留空数据报和报文边界，60 秒无流量后释放；停止、到期、删除与权限撤销都会释放监听和已有会话。会话上限为 1024，发送队列有界，超过限制会丢包。

## 理解流向

请求方向为：访问者 → 入口监听端口 → 隧道传输 → 出口机器 → 目标服务。TCP 响应沿同一连接返回；UDP 响应返回对应来源地址/端口。

- 监听地址属于入口机器。`127.0.0.1` 仅允许入口机器自身访问；`0.0.0.0` 监听所有 IPv4 网卡；也可指定 IPv6 地址。
- 目标地址由出口机器解析、访问。目标填 `127.0.0.1` 表示出口机器自身，不是堡垒机或访问者的本机。
- 入口、出口均支持堡垒机、Agent 和普通 SSH 机器。SSH 跳板链路沿用机器已有的代理配置。
- SSH 入口使用远程端口转发，出口使用 SSH 的 `direct-tcpip` 转发。SSH 服务须允许转发；对外监听还须配置 `GatewayPorts` 和防火墙。
- 配置预览中的实线箭头表示请求流向，虚线说明建立 SSH 连接使用的跳板链路。

组织 owner/admin 管理本组织的隧道；系统管理员也可管理。堡垒机本身作为端点仅对系统管理员开放。端点及每个跳板必须属于配置所在组织。运行时继续检查操作者权限和机器是否存在；撤销权限会停止现有连接。

## 持久配置与启停

配置保存在主库。启动服务即恢复已启用配置，不需要再次登录控制台。Agent 离线时保留配置，重新上线后自动恢复监听。

启用时按配置时长计算到期时间，重连或重启不会延长。重新计时会重新启用并计算新的到期时间。修改配置会重建运行中的隧道，新时长在下次启用时生效。停止、删除、到期和权限撤销均关闭现有连接。

配置恢复与 TCP 连接恢复不同：进程重启或 Agent 真正断线后会恢复监听，原有应用 TCP 连接需要重新建立。

## 直连与回退

两端为 Agent，或 SSH 机器的跳板链路可以分别委托给两端 Agent 时，先通过堡垒机传输，并在后台协商 WebRTC/ICE 直连。SSH 跳板委托使用服务端已验证的固定主机公钥和本条隧道需要的凭据，不改变 SSH 的主机身份校验。

直连使用 DTLS 加密、ICE 候选检查及 STUN UDP 打洞。公网直连取决于 NAT 和防火墙，不能保证所有网络都成功；无法直连时继续使用中转。

服务端参数：

```sh
# 默认优先使用国内公共 STUN，并包含 Google、Cloudflare 公共 STUN；多个地址以逗号分隔。
gosshd-server --tunnel-stun-servers 'stun:stun.miwifi.com:3478,stun:stun.chat.bilibili.com:3478,stun:stun.hitv.com:3478,stun:stun.l.google.com:19302,stun:stun.cloudflare.com:3478'

# 仅尝试本地网卡候选，不访问公共 STUN。
gosshd-server --tunnel-stun-servers ''
```

字节流使用独立于路径的序号、确认、有限发送窗口、重传和去重。切换为直连以及直连失败回退中转时，保留入口、目标 TCP socket 和 SSH 连接，按顺序交付数据。页面展示实际中转、直连及混合连接状态。堡垒机控制链路需要保持在线。

悬停或聚焦运行状态/传输状态可查看实际网络路径；手机可点击状态打开详情。两端 Agent 分别上报选中的 ICE 路径，显示出口网卡、本地 IP/端口、选中候选 IP/端口、对端地址、IPv4/IPv6、UDP、候选类型、可用的往返延迟及上报时间。STUN 公网映射地址与本地网卡地址分开显示。识别不到网卡时显示“未识别”，不会用配置字段猜测。多条连接分别列出，悬浮详情最多显示最近上报的 16 条。

端口转发按入口/出口链路协商直连传输，TCP 连接与 UDP 会话通过独立多路复用流共享链路。纯 SSH 机器间使用 SSH 转发和堡垒机中转，不在普通 SSH 主机上安装额外的打洞程序。

## 共享 P2P 通道与 Agent 代理

网页文件上传/下载与 Agent TCP 隧道使用相同的通道策略：鉴权和目标连接准备好后立即中转，后台协商 ICE，收到直连探测确认后切换；直连发送失败或数据确认超时则沿原通道回退，失败的 ICE 协商会后台重试。序号、确认、发送窗口、重传和去重属于通道层，不属于上传或下载业务。业务启动与直连切换不使用固定 sleep；SDP 立即发送，ICE 候选产生后增量交换（Trickle ICE），不会等待候选全部收集完成。重传、后台重试和超时/闲置清理的定时器不阻塞首包。

浏览器实现为 `web/src/p2pChannel.ts` 的 `P2PChannel`，Agent 实现为 `internal/tunnel.Conn`。文件操作只处理服务端授权后的文件路径、记录校验、读写和完成回执；同一目标/方向的后续文件复用通道，文件完成不会中断仍在进行的直连协商。下载使用约 256 KiB 的有界写入批次，最终接收回执须等全部数据被保存端接受。

目标为经 Agent 访问的普通 SSH 主机时，直连对象是 Agent，而不是最终主机：

`网页/入口 Agent → P2P → 出口 Agent → SSH/SFTP/TCP → 目标主机`

跳板路由、凭据和固定主机公钥由服务端验证后委托给 Agent。直连切换只替换到 Agent 的传输路径，不重建 Agent 到 SSH 主机的连接，也不取消每次文件操作的授权和审计。直连后的业务数据不再经堡垒机转发；信令、授权和可信状态/审计控制仍需要堡垒机在线。

减少服务器流量的前提是业务入口不在堡垒机自身。例如隧道监听在堡垒机上，访问流量已经进入堡垒机，不能仅靠出口直连消除这部分服务器流量。小文件也可能在直连准备好前通过中转完成；不应为了追求“零中转字节”阻塞首次传输。

## 审核库统计

`--audit-database-path` 对应的独立审核库保存流量统计，不在主库累积流量历史。

- 上传：入口向目标发送的数据；下载：目标向入口返回的数据。
- 中转流量由服务端计算；直连流量由入口 Agent 上报累计计数。
- 只计 TCP 数据负载；信令、ACK、加密开销和重复传输不重复计入业务流量。
- 当前并发连接、累计成功连接、时间桶内新建连接和峰值并发均可查询。
- 每 5 分钟按 UTC 对齐一个时间桶，在边界落盘；停止、重建、删除及正常关闭服务时补记未完成的时间桶。
- Agent 每秒上报累计直连计数，用于实时显示；持久历史仍按 5 分钟聚合。
- 当前时间桶为暂存数据。强制终止进程会丢失尚未落盘部分；突发 Agent 网络中断可能丢失尚未上报的直连计数。

审核库的 `tunnel_traffic` 以 `(tunnel_id, source_ip, bucket_start)` 为主键，支持时间范围和来源 IP 查询；`tunnel_traffic_totals` 在同一事务中累积总量。空 `source_ip` 保存隧道整体统计，避免重复计数，并独立记录整体峰值并发。删除隧道后审核历史保留。

「统计」弹窗可查询最近 24 小时、7 天、30 天或自定义时间范围（最长 31 天），分别查看上传/下载趋势、直连/中转流量、新建连接和峰值并发。IP 来源列表展示每个 IP 的流量、所选时段新建连接、峰值并发与当前并发，支持按流量或新建连接数升降序排序。点击列表 IP 或输入 IP 筛选后，趋势图、汇总和列表均只显示该来源；「全部 IP」恢复整体统计。时间范围扩展至完整的五分钟统计区间。

来源 IP 取入口 TCP 连接或 UDP 数据报的远端地址；Agent 入口需同步升级以传递此地址，旧 Agent 或不可识别的地址显示为「未知来源」。SSH 临时本地转发按 SSH 客户端来源统计，远程转发按入口 TCP 来源统计。升级时审核库迁移 `0003_tunnel_source_traffic.sql` 会一次性重建两个统计表，直接丢弃旧统计，不转换旧数据；隧道配置和命令审计日志保留。

## API

所有接口要求登录及组织管理员权限：

- `GET /api/tunnels?organization_id=...`
- `POST /api/tunnels`：保存配置，默认停止。
- `PUT /api/tunnels/{id}`：修改配置。
- `POST /api/tunnels/{id}/enable`：启用或重新计时。
- `POST /api/tunnels/{id}/stop`
- `DELETE /api/tunnels/{id}`
- `GET /api/tunnels/{id}/traffic?from=...&to=...&source_ip=...`：Unix 秒范围，上限 31 天，返回 `interval_seconds: 300`、补齐空时间桶的 `buckets`、来源列表 `sources` 和当前并发 `active_connections`。`to` 为排他边界；可选 `source_ip` 支持 IPv4、IPv6 或 `unknown`。

配置字段为 `organization_id`（创建时）、`name`、`entry_target_id`、`listen_host`、`listen_port`、`exit_target_id`、`destination_host`、`destination_port`、`duration_seconds`。空端点 ID 表示堡垒机，时长 `0` 表示永久，最大 365 天。

## 验证

专项测试覆盖二进制传输、丢包/乱序、真实 WebRTC 直连与回退、TCP 半关闭完整响应、SSH 入口及跳板、SSH 经 Agent 的 P2P、Agent 重连、服务重启、到期、权限撤销、组织隔离及审核库时间桶/累计计数。

## MCP 管理

在「密钥与 MCP」为令牌开启 **隧道管理（`tunnel`）** 工具分组，连接现有 `/mcp` 端点即可。原有令牌默认仍仅允许终端会话工具，不会自动获得隧道权限。所有隧道操作都检查当前账号状态和组织管理员权限；入口、出口、跳板链必须属于同一组织，堡垒机端点仅系统管理员可选。

| 工具 | 操作 |
| --- | --- |
| `tunnel_list` | 按 `organization_id` 查询持久隧道与当前 SSH 临时转发 |
| `tunnel_get` | 按 `tunnel_id` 获取配置、创建者、实时状态、连接数、累计流量及实际直连网络路径 |
| `tunnel_create` | 创建持久配置，默认停止；创建者来自认证账号，不能伪造 |
| `tunnel_update` | 部分更新配置；省略字段保留原值，组织与创建者不可更改 |
| `tunnel_enable` | 按配置时长启用或重新计时；再次启用会关闭现有连接 |
| `tunnel_stop` | 停止并关闭现有连接；持久配置和审核统计保留 |
| `tunnel_delete` | 删除持久配置；审核库历史统计保留 |
| `tunnel_traffic` | 查询五分钟流量、连接数、峰值并发和来源 IP 列表；可通过 `source_ip` 筛选，包含尚未落库数据 |

创建示例（`entry_target_id` / `exit_target_id` 为现有机器 ID，支持 Agent、普通 SSH 与其跳板链）：

```json
{
  "protocol": "port",
  "transports": ["tcp"],
  "organization_id": "organization-id",
  "name": "数据库维护",
  "entry_target_id": "entry-machine-id",
  "listen_host": "127.0.0.1",
  "listen_port": 15432,
  "exit_target_id": "exit-machine-id",
  "destination_host": "127.0.0.1",
  "destination_port": 5432,
  "duration_seconds": 3600
}
```

拿到返回的 `tunnel.id` 后，调用 `tunnel_enable`，参数为 `{"tunnel_id":"返回的 ID"}`。`duration_seconds: 0` 表示永久。修改正在运行的隧道会重建链路并关闭已有连接，原到期时间保持不变；新时长在下次启用时生效。流量工具的 `from` / `to` 为 Unix 秒，区间左闭右开，默认最近 24 小时，最多约 31 天。

## SSH 命令创建的临时转发

**经过本堡垒机 SSH 入口**的 `ssh -L`、`ssh -D` 实际转发连接和 `ssh -R` 监听器，会自动出现在组织的隧道管理页面与 MCP 列表中，标记为「SSH 临时转发」。显示认证创建者、来源地址和公钥指纹，统计服务器中转流量、连接数、峰值并发；通过界面或 `tunnel_stop` 可以关闭转发连接及对应远程监听器。其他 SSH 会话及其他转发不受影响。客户端 `cancel-tcpip-forward` 也会真正释放对应监听端口。SSH 转发审核日志的 `session_id` 对应临时隧道 ID，便于关联历史流量与创建者。

临时转发由 SSH 客户端维持，结束后移出活动列表；原有 SSH 转发审核日志和审核库流量统计保留。它不会变成持久配置，不能从服务器重新启用或编辑，需在客户端重新创建。

SSH 协议只向服务器披露实际 `direct-tcpip` 通道的目标，因此 `-L` / `-D` 在有访问连接时逐条展示，服务器不知道客户端监听端口，也不能在尚未创建通道时发现空闲的本地监听器。对于 `-R`，服务器知道自己的监听端口，但不知道客户端最终访问的目标。界面明确标记未知部分，不推测端口或网络流向。独立连接其他 SSH 服务器、没有经过本堡垒机的转发不可自动发现；若需永久统一配置，可使用上述持久隧道功能。

## 配置迁移与升级

主库迁移 `0006_port_tunnels.sql` 在服务启动时自动执行：历史隐式 TCP（缺失或空 `protocol`）及显式 `protocol: "tcp"` 转为 `protocol: "port"`、`transports: ["tcp"]`，同时递增所有配置的版本以替换在线 Agent 的旧部署/路由缓存。HTTP 配置、启停状态、到期时间和端口保持不变。新 API/MCP 不再接受旧 TCP 类型；端口配置未传 `transports` 时默认 TCP，显式空数组会被拒绝。仅 UDP 使用 `["udp"]`，双协议使用 `["tcp", "udp"]`。

服务器和参与隧道的 Agent 应一起升级。Agent 的旧部署缓存不做兼容转换，由服务器下发迁移后的新版本覆盖；首次同步前旧缓存不会以旧 TCP 类型启动。UDP 经可靠字节流封装传输，保留数据报边界，不等价于原生无序/不可靠 UDP 传输。监听公网地址时请按所选协议开放防火墙规则。
