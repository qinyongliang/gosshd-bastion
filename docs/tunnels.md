# 持久 TCP 隧道

控制台的「隧道管理」用于配置入口机器、监听地址/端口、出口机器、目标地址/端口，以及永久或定时启用。

## 理解流向

请求方向为：访问者 → 入口监听端口 → 隧道传输 → 出口机器 → 目标服务。响应沿同一条连接返回。

- 监听地址属于入口机器。`127.0.0.1` 仅允许入口机器自身访问；`0.0.0.0` 监听所有 IPv4 网卡；也可指定 IPv6 地址。
- 目标地址由出口机器解析、访问。目标填 `127.0.0.1` 表示出口机器自身，不是堡垒机或访问者的本机。
- 入口、出口均支持堡垒机、Agent 和普通 SSH 机器。SSH 跳板链路沿用机器已有的代理配置。
- SSH 入口使用远程端口转发，出口使用 SSH 的 `direct-tcpip` 转发。SSH 服务须允许转发；对外监听还须配置 `GatewayPorts` 和防火墙。
- 配置预览中的实线箭头表示请求流向，虚线说明建立 SSH 连接使用的跳板链路。

组织 owner/admin 管理本组织的隧道；系统管理员也可管理。堡垒机本身作为端点仅对系统管理员开放。端点及每个跳板必须属于配置所在组织。运行时继续检查操作者权限和机器是否存在；撤销权限会停止现有连接。

## 持久配置与启停

配置保存在主库。启动服务即恢复已启用配置，不需要再次登录控制台。Agent 离线时保留配置，重新上线后自动恢复监听。

启用时按配置时长计算到期时间，重连或重启不会延长。重新计时会重新启用并计算新的到期时间。修改配置会重建运行中的隧道，新时长在下次启用时生效。停止、删除、到期和权限撤销均关闭现有连接。

配置恢复与 TCP 连接恢复不同：进程重启或 Agent 真正断线后会恢复监听，原有应用 TCP 连接需要重新建立。

## 直连与回退

两端为 Agent，或 SSH 机器的跳板链路可以分别委托给两端 Agent 时，先通过堡垒机传输，并在后台协商 WebRTC/ICE 直连。SSH 跳板委托使用服务端已验证的固定主机公钥和本条隧道需要的凭据，不改变 SSH 的主机身份校验。

直连使用 DTLS 加密、ICE 候选检查及 STUN UDP 打洞。公网直连取决于 NAT 和防火墙，不能保证所有网络都成功；无法直连时继续使用中转。

服务端参数：

```sh
# 默认公共 STUN；也可替换成自建服务，多个地址以逗号分隔。
gosshd-server --tunnel-stun-servers 'stun:stun.l.google.com:19302'

# 仅尝试本地网卡候选，不访问公共 STUN。
gosshd-server --tunnel-stun-servers ''
```

字节流使用独立于路径的序号、确认、有限发送窗口、重传和去重。切换为直连以及直连失败回退中转时，保留入口、目标 TCP socket 和 SSH 连接，按顺序交付数据。页面展示实际中转、直连及混合连接状态。堡垒机控制链路需要保持在线。

悬停或聚焦运行状态/传输状态可查看实际网络路径；手机可点击状态打开详情。两端 Agent 分别上报选中的 ICE 路径，显示出口网卡、本地 IP/端口、选中候选 IP/端口、对端地址、IPv4/IPv6、UDP、候选类型、可用的往返延迟及上报时间。STUN 公网映射地址与本地网卡地址分开显示。识别不到网卡时显示“未识别”，不会用配置字段猜测。多条连接分别列出，悬浮详情最多显示最近上报的 16 条。

当前实现为每条 TCP 连接协商独立的直连传输。纯 SSH 机器间使用 SSH 转发和堡垒机中转，不在普通 SSH 主机上安装额外的打洞程序。

## 审核库统计

`--audit-database-path` 对应的独立审核库保存流量统计，不在主库累积流量历史。

- 上传：入口向目标发送的数据；下载：目标向入口返回的数据。
- 中转流量由服务端计算；直连流量由入口 Agent 上报累计计数。
- 只计 TCP 数据负载；信令、ACK、加密开销和重复传输不重复计入业务流量。
- 当前并发连接、累计成功连接、时间桶内新建连接和峰值并发均可查询。
- 每 5 分钟按 UTC 对齐一个时间桶，在边界落盘；停止、重建、删除及正常关闭服务时补记未完成的时间桶。
- Agent 每秒上报累计直连计数，用于实时显示；持久历史仍按 5 分钟聚合。
- 当前时间桶为暂存数据。强制终止进程会丢失尚未落盘部分；突发 Agent 网络中断可能丢失尚未上报的直连计数。

审核库的 `tunnel_traffic` 以 `(tunnel_id, bucket_start)` 为主键，支持时间范围查询；`tunnel_traffic_totals` 在同一事务中累积总量，使列表查询不扫描历史。删除隧道后审核历史保留。

页面可查询最近 24 小时、7 天、30 天，分别查看上传/下载趋势、直连/中转流量、新建连接和峰值并发。

## API

所有接口要求登录及组织管理员权限：

- `GET /api/tunnels?organization_id=...`
- `POST /api/tunnels`：保存配置，默认停止。
- `PUT /api/tunnels/{id}`：修改配置。
- `POST /api/tunnels/{id}/enable`：启用或重新计时。
- `POST /api/tunnels/{id}/stop`
- `DELETE /api/tunnels/{id}`
- `GET /api/tunnels/{id}/traffic?from=...&to=...`：Unix 秒范围，上限 31 天，返回 `interval_seconds: 300` 和补齐空时间桶的序列。`to` 为排他边界。

配置字段为 `organization_id`（创建时）、`name`、`entry_target_id`、`listen_host`、`listen_port`、`exit_target_id`、`destination_host`、`destination_port`、`duration_seconds`。空端点 ID 表示堡垒机，时长 `0` 表示永久，最大 365 天。

## 验证

专项测试覆盖二进制传输、丢包/乱序、真实 WebRTC 直连与回退、TCP 半关闭完整响应、SSH 入口及跳板、SSH 经 Agent 的 P2P、Agent 重连、服务重启、到期、权限撤销、组织隔离及审核库时间桶/累计计数。
