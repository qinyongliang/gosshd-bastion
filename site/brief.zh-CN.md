## 一句话介绍

GOSSHD Bastion 是人和 AI 共用的远程运维工作台，把 SSH 终端、文件管理、私有节点和 TCP 隧道整合到统一入口，并提供权限控制、命令审查与审计回放。

## 适合转发的短介绍

远程运维不应该在终端、文件工具、隧道配置和权限台账之间反复切换。GOSSHD Bastion 将这些工作放进一个自托管工作台：团队在浏览器中排障、编辑配置和批量传输文件；AI Agent 通过标准 SSH 或 MCP 参与巡检与辅助排障。目标服务器凭证由网关管理，访问范围由组织、用户组和策略约束，SSH exec 命令按规则及可选 LLM 审查后转发，命令审计和已启用的会话录制为复盘留下记录。

## 30 秒产品讲解

- **工作集中：** 网页终端、文件编辑、多选文件操作和服务隧道不再分散。
- **人机共用：** 浏览器适合团队日常操作，SSH 兼容已有工具，MCP 提供 AI 工具入口。
- **边界明确：** 目标与标签绑定、用户组、来源 IP 和能力开关一起约束访问。
- **过程可查：** 命令判定、退出码、文件传输审计，以及开启录制后的终端回放，便于追溯。
- **自行部署：** 控制面、目标凭证和审计存储由部署方管理；可选 LLM 按自己的配置接入。

## 能力概览

| 能力 | 能做什么 | 需要知道的边界 |
| --- | --- | --- |
| 网页工作台 | 远程终端、文件编辑与可调整布局，支持桌面和手机访问 | 页面示意不是实时控制台；实际使用需自行部署 |
| 文件管理 | 文件夹递归上传；多选、框选；批量复制、移动、下载与删除 | 上传上限 1 GiB，下载方式受浏览器能力影响 |
| 传输链路 | 浏览器与新版 Agent 尝试加密 WebRTC 直连，不可直连时中转 | 不保证任何网络都能打洞；仍按文件鉴权与审计 |
| 私有节点 | Agent 主动连接网关，已有 SSH 服务也可以接入 | 需要网络可达及正确的节点、目标和凭证配置 |
| TCP 隧道 | 管理入口、出口、目标、有效期、连接数、流量与来源 IP | SSH 转发、对外监听及防火墙仍需正确配置 |
| 权限治理 | 组织、用户组、目标、标签、来源 IP 与能力开关 | 应先在测试环境验证策略，遵循最小权限 |
| 命令审查 | SSH exec 使用黑白名单及可选 LLM；模型审核异常默认拒绝 | 不是完整 Shell 沙箱，不保证识别所有危险操作 |
| 临时授权 | 指定服务的限时 SSH 授权，到期或删除会断开连接 | UUID 是敏感访问凭证，策略与审计身份沿用创建者 |
| 审计与回放 | 命令、判定、退出码与文件审计；录制开启后的交互会话回放 | 并非所有操作都有回放，需正确配置录制与存储 |
| MCP | 按令牌工具分组授权终端与隧道管理 | 仍受账号状态和组织权限约束，不自动获得管理员能力 |

## 三类典型场景

### 运维与开发

查看日志 → 编辑配置 → 传输发布文件 → 按需连接内网服务。把常见操作集中在网页工作台，减少工具切换。

### AI 辅助运维

让 Agent 使用 SSH 或 MCP 执行巡检与辅助排障。调用方使用自己的 SSH 身份或 MCP 令牌，不需要直接持有目标服务器凭证；命令判定取决于实际绑定的规则和可选模型。

### 内网与客户现场

通过私有节点接入机房、VPC 和客户现场机器；按组织划分目标和成员，并按实际网络条件选择直连或中转链路。

## 开始使用

1. 从 Releases 下载适合平台的 server 包，按 README 部署。
2. 配置访问地址、初始管理员和生产 HTTPS，妥善保存数据库与密钥。
3. 添加一台测试 SSH 主机，或按控制台安装命令注册私有节点。
4. 设置目标别名、用户组和命令策略，验证允许、拒绝及审计结果。
5. 再接入团队成员与 AI 工具，逐步扩大使用范围。

示例（请替换域名、端口和目标别名，并配置调用方 SSH 身份）：

```sh
ssh -p 22022 prod-api@bastion.example.com "uptime"
```

## 对外介绍时不要夸大

- 不承诺“绝对安全”“永远直连”“零延迟”或“无限文件大小”。
- 不把 SSH exec 命令审查说成完整 Shell 沙箱。
- 不把“目标凭证不直接交给 AI”说成“调用方不需要身份凭证”。
- 不把临时授权说成可公开分享的免认证链接。
- 不宣称产品是已提供 SLA 的托管服务，不使用未验证的客户数量、性能或合规认证。
