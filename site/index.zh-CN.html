BUILT FOR REAL OPERATIONS

不只是连上，更要管得住。

把日常运维与访问治理放在一起，而不是事后再补一层管理。

01

组织与用户组

按组织、目标、标签和用户组绑定访问策略，结合来源 IP 与能力开关控制访问范围。

02

命令规则与 AI 审查

SSH exec 命令先走黑白名单；未命中时可交由配置的 LLM 审查。模型审核异常默认拒绝。

03

临时 SSH 授权

为指定服务生成限时授权，到期或删除即断开相关连接。授权标识本身是敏感访问凭证。

04

命令审计与终端回放

查询命令、判定和退出码；对已启用录制的交互式会话，沿时间轴回放操作过程。

05

AI 的 MCP 入口

通过 /mcp 接入工具。终端与隧道工具按令牌分组授权，操作继续受账号和组织权限约束。

06

私有节点与已有 SSH

已有 SSH 服务可以直接添加；私有节点通过 Agent 主动连接网关，接入内网与现场机器。

在开始之前，你可能想知道

需要把目标服务器的私钥交给 AI 吗？+

不需要把目标服务器凭证直接交给 Agent；这些凭证由网关管理。调用方仍需配置自己的 SSH 身份或 MCP 令牌，也可以使用受控的临时授权。

P2P 是否保证能直连？+

不保证。直连取决于 Agent 版本、浏览器、STUN 配置、网络与防火墙；不可直连时使用中转。网页上传仍有 1 GiB 上限，下载方式也受浏览器能力影响。

临时授权可以随意分享吗？+

不可以。持有授权 UUID 就能在有效期内访问对应服务，策略和审计身份沿用创建者。只向可信接收方提供，使用后及时删除。

命令审查能保证所有操作都安全吗？+

不能。规则质量、策略配置和模型输出都影响结果。SSH exec 审查不等于对所有交互式 Shell 输入进行完整隔离；应结合最小权限、能力开关与独立备份。

这是托管服务，还是自己部署的软件？+

这里介绍的是自托管软件。服务端、目标接入、数据库、审计存储和可选 LLM 接口由你部署与配置；页面中的工作台和数据均为功能示意。
